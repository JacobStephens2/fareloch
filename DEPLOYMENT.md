# Deployment

Fareloch runs on a single Ubuntu server with Apache serving the static frontend and reverse-proxying API requests to a Node.js backend.

**Primary domain:** `https://fareloch.app`  
**Legacy alias:** `https://macros.stephens.page` (path-preserving 301 to `fareloch.app`)

## Architecture

```
Browser
  │
  ├─ Static files (HTML/CSS/JS/icons) ──► Apache ──► /var/www/macros.stephens.page/dist/
  │
  └─ /api/* requests ──► Apache (ProxyPass) ──► Node.js on port 3457
```

- **Frontend**: Vite builds static assets into `dist/`. Apache DocumentRoot points at that directory. The app uses hash-based routing (`#/login`, `#/recipes`, etc.), so Apache always serves `index.html` — no server-side routing needed.
- **Backend**: Express server compiled from TypeScript, managed by systemd, listening on `localhost:3457`. Apache proxies any request starting with `/api` to this backend.
- **Database**: SQLite file under the server `data/` directory. Schema auto-creates on first run and auto-migrates on restart.
- **SSL**: Let's Encrypt certificates via Certbot, auto-renewed (`fareloch.app` primary; `macros.stephens.page` retained for the redirect vhost).
- **PWA**: Service worker generated by vite-plugin-pwa precaches the app shell. The `manifest.webmanifest` and `assetlinks.json` for TWA are served as static files.

## Server Components

### Apache Virtual Hosts

**Primary HTTP** (`/etc/apache2/sites-available/fareloch.app.conf`):
Redirects HTTP → HTTPS; canonicalizes `www` → apex.

**Primary HTTPS** (`/etc/apache2/sites-available/fareloch.app-le-ssl.conf`):
```apache
<VirtualHost *:443>
    ServerName fareloch.app
    ServerAlias www.fareloch.app
    DocumentRoot /var/www/macros.stephens.page/dist

    <Directory /var/www/macros.stephens.page/dist>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    RewriteEngine On
    RewriteCond %{HTTP_HOST} ^www\.fareloch\.app$ [NC]
    RewriteRule ^ https://fareloch.app%{REQUEST_URI} [END,NE,R=permanent]

    ProxyPreserveHost On
    ProxyPass /api http://127.0.0.1:3457/api
    ProxyPassReverse /api http://127.0.0.1:3457/api

    SSLCertificateFile /etc/letsencrypt/live/fareloch.app/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/fareloch.app/privkey.pem
    Include /etc/letsencrypt/options-ssl-apache.conf
</VirtualHost>
```

**Legacy HTTPS** (`macros.stephens.page`): path-preserving 301 to `https://fareloch.app%{REQUEST_URI}`.

Required Apache modules: `proxy`, `proxy_http`, `ssl`, `rewrite`.

### Systemd Service

**Unit file** (`/etc/systemd/system/macros-api.service`):
```ini
[Unit]
Description=Fareloch API
After=network.target

[Service]
Type=simple
User=jacob
WorkingDirectory=/var/www/macros.stephens.page/server
ExecStart=/usr/bin/node dist/index.js
Restart=on-failure
RestartSec=5
Environment=NODE_ENV=production
Environment=PORT=3457
Environment=APP_URL=https://fareloch.app
# … secrets via secret-env / sops (JWT, SMTP, API keys)

[Install]
WantedBy=multi-user.target
```

## Deploy Steps

### Frontend

```bash
cd /var/www/macros.stephens.page
npm run build
```

### Backend

```bash
cd /var/www/macros.stephens.page/server
npx tsc
sudo systemctl restart macros-api
```

### Android APK

The web deploy serves from `fareloch.app`, so `API_BASE` defaults to the same-origin `/api`. Native Capacitor defaults to `https://fareloch.app/api`; `VITE_API_BASE` overrides either default. Always build the app with `build:android`, which selects Android mode to omit the PWA service worker and syncs the bundled assets:

```bash
npm run build:android   # Android mode + VITE_API_BASE=https://fareloch.app/api + cap sync
cd android && JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./gradlew assembleRelease
# signed APK: android/app/build/outputs/apk/release/app-release.apk
```

Native startup unregisters leftover service workers and clears CacheStorage from
older APKs before checking authentication. It preserves localStorage, including
guest data and login tokens. Web startup registers the PWA worker and retains its
offline caches.

### Verify

```bash
sudo systemctl status macros-api
curl -s https://fareloch.app/api/health
curl -sI https://macros.stephens.page/ | head -5   # expect 301 → fareloch.app

sudo apache2ctl configtest
sudo systemctl status apache2
sudo journalctl -u macros-api -f
```

## Updating Environment Variables

Edit the systemd service file (or the sops env it loads), then reload:

```bash
sudo vim /etc/systemd/system/macros-api.service
sudo systemctl daemon-reload
sudo systemctl restart macros-api
```

## SSL Certificate Renewal

Certbot handles automatic renewal via a systemd timer. To manually renew:

```bash
sudo certbot renew
```

## Notes on domain cutover

- Auth cookies are host-only (no `Domain=` attribute). After switching to `fareloch.app`, users must log in again on the new origin.
- `APP_URL` drives email verification and password-reset links — keep it on `https://fareloch.app`.
- TWA / Digital Asset Links are origin-bound; re-verify `assetlinks.json` on `fareloch.app` before updating the Play listing.
